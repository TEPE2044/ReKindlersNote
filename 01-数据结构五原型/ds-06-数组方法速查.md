# 第一章 · 数据结构 06：数组方法速查

写用例数组时，记得某个方法名，不一定就能选对方法：筛出一批、找第一条、判断有没有，对应的是不同的意图。本节按“要做什么”来选方法，不按 API 名称背清单。

测试结果常常是对象数组。选错方法会多做转换，或拿到和预期不同的返回值。这一节是一张常用方法对照表；前五节的数据结构与算法练习仍是本章主体。

## 留下符合条件的，或把每个元素改写

| 意图 | 方法 | 返回结果 | 记法 |
|---|---|---|---|
| 留下符合条件的元素 | `filter` | 新数组，长度可能变短 | 要一批 |
| 把每个元素转换成新值 | `map` | 新数组，长度不变 | 一对一改写 |

`filter` 的回调返回真值就留下，`map` 的回调则为每个元素产生一个新值。两者都不改原数组。

```js
const durations = [120, 800, 350, 1200];

console.log(durations.filter((ms) => ms >= 500));
// [800, 1200]

console.log(durations.map((ms) => Math.round(ms / 1000)));
// [0, 1, 0, 1]

console.log(durations);
// [120, 800, 350, 1200]
```

链式调用时，先筛选再转换：`arr.filter(...).map(...)`。`filter` 决定哪些元素留下，`map` 决定留下的元素变成什么。

## 找元素、找位置，还是只要是/否

这四个方法经常混淆，先确定结果需要什么：

| 意图 | 方法 | 找到 / 满足时 | 没找到 / 不满足时 |
|---|---|---|---|
| 要那个元素 | `find` | 元素本身 | `undefined` |
| 要元素的位置 | `findIndex` | 下标 | `-1` |
| 是否至少有一个符合 | `some` | `true` | `false` |
| 是否全部符合 | `every` | `true` | `false` |

```js
const runs = [
  { id: "r-1", status: "passed" },
  { id: "r-2", status: "failed" },
];

console.log(runs.find((run) => run.status === "failed"));
// { id: 'r-2', status: 'failed' }
console.log(runs.findIndex((run) => run.id === "r-2"));
// 1
console.log(runs.some((run) => run.status === "failed"));
// true
console.log(runs.every((run) => run.status === "passed"));
// false
console.log(runs.find((run) => run.id === "missing"));
// undefined
```

**坑**：`find` 找不到返回 `undefined`，不是 `null`。这时继续读取 `.title` 会抛 `TypeError`，要先判断是否找到。

## 汇总成一个值

`reduce` 把数组逐项累积成一个结果。第二个参数是初始值，建议总是提供：这样空数组也有明确结果，而且累积值的类型可预测。

```js
const durations = [120, 800, 350, 1200];

console.log(durations.reduce((total, ms) => total + ms, 0));
// 2470

try {
  [].reduce((total, value) => total + value);
} catch (error) {
  console.log(error.name);
}
// TypeError

console.log([].reduce((total, value) => total + value, 0));
// 0
```

不给初始值时，非空数组的第一个元素会成为初始累积值；空数组则会抛 `TypeError`。对对象数组求耗时总和时不传初始值，累积值从第一个对象开始，`对象 + 数字` 变成字符串拼接，实测得到 `"[object Object]80050023000"`，不是数字。

## 去重：Set 比较对象的引用

`Set` 可以按值去重基本类型；对象则按引用比较。两个对象属性相同，但只要是分别创建的两个对象，引用就不同，`Set` 会都保留。

```js
const first = { id: 1 };
const separate = { id: 1 };

console.log(new Set([first, first, separate]).size);
// 2：同一个对象引用只保留一次，另一个对象引用不同
console.log(new Set([1, 1, 2]).size);
// 2
```

因此，按对象的 `id` 去重不能直接把对象数组传给 `Set`；需要按 `id` 记录已经见过的项。`Map` 也能按 key 记录，本节不展开。

## 修改原数组，还是返回新数组

| 方法 | 修改原数组 | 用途 / 说明 |
|---|---|---|
| `sort`、`reverse`、`splice` | 是 | 排序、翻转、删插替 |
| `push`、`pop`、`unshift`、`shift` | 是 | 从数组两端增删元素 |
| `slice`、`map`、`filter` | 否 | 返回新数组 |
| `toSorted`、`toReversed` | 否 | 返回新数组；Node.js 20 及以上支持，老版本先 `slice()` 复制再操作 |

`sort()` 还有一个常见坑：不传比较函数时，默认按字符串顺序比较。

```js
const scores = [10, 9, 1];
console.log(scores.sort());
// [1, 10, 9]：默认按字符串比较
console.log(scores);
// [1, 10, 9]：原数组已改变

const original = [10, 9, 1];
console.log(original.toSorted((a, b) => a - b));
// [1, 9, 10]
console.log(original);
// [10, 9, 1]：原数组未改变
```

## 练习

```js
const cases = [
  { id: 101, title: "登录成功", module: "登录", status: "passed", duration: 1200 },
  { id: 102, title: "登录失败", module: "登录", status: "failed", duration: 800 },
  { id: 103, title: "退出登录", module: "登录", status: "passed", duration: 500 },
  { id: 104, title: "新增用例", module: "用例", status: "passed", duration: 2300 },
  { id: 105, title: "编辑用例", module: "用例", status: "skipped", duration: 0 },
];
```

**Q1. 链式与空结果。** 用一行 `filter(...).map(...)` 输出「用例」模块所有用例的标题；再把筛选条件换成「用例」模块里 `status` 为 `failed` 的用例，输出结果的长度。

验收：

```text
["新增用例", "编辑用例"]
0
```

**Q2. 对照。** 分别输出：是否所有用例的 `duration` 都大于 0；第一条 `duration` 为 0 的用例标题；`duration` 大于 3000 的用例下标。

验收：

```text
false
编辑用例
-1
```

**Q3. 对象去重。** 下面两行输出的 Set 大小不同，说明为什么一个是 `5`、一个是 `3`；再按 `id` 去重，输出保留的 `name`：

```js
const dup = [
  { id: 1, name: "登录成功" },
  { id: 2, name: "登录失败" },
  { id: 1, name: "登录成功-改" },
  { id: 3, name: "新增用例" },
  { id: 2, name: "登录失败-改" },
];

console.log(new Set(dup).size);
console.log(new Set(dup.map((item) => item.id)).size);
```

验收：

```text
5
3
["登录成功", "登录失败", "新增用例"]
```

**Q4. 汇总。** 用 `reduce` 算出所有用例的耗时总和；再用一行链式算出状态为 `passed` 的用例耗时总和。

验收：

```text
4800
4000
```

## 答案（先做完再看）

<details>
<summary>Q1 验收要点</summary>

- 先 `filter` 按模块筛，再 `map` 取标题，链式写在一行。
- 「用例」模块没有失败用例：`filter` 返回空数组，`map` 之后仍是空数组，长度为 `0`，不报错。
- 两个方法都返回新数组，`cases` 不变。

</details>

<details>
<summary>Q2 验收要点</summary>

- 有一条 `duration` 为 `0` 的用例（105），所以 `every` 是 `false`。
- `find` 拿到的是元素本身，再读 `.title` 得到“编辑用例”。
- 没有 `duration` 大于 3000 的用例，`findIndex` 返回 `-1`。只问“有没有”用 `some`；要位置才用 `findIndex`。

</details>

<details>
<summary>Q3 验收要点</summary>

- `new Set(dup).size` 是 `5`：五个对象是五个不同引用，一个都没去掉。
- `new Set(dup.map((item) => item.id)).size` 是 `3`：id 是基本类型，按值去重。
- 按 `id` 去重时，要保存已见 id，并只保留每个 id 的第一项。

</details>

<details>
<summary>Q4 验收要点</summary>

- 全部耗时总和是 `4800`；`passed` 的三条（101、103、104）合计 `4000`。
- `reduce` 第二个参数要给 `0`：对象数组不传初始值时，累积值从第一个对象开始，`对象 + 数字` 变成字符串拼接，得不到数字。
- 可以先 `filter` 再 `reduce`，链式写在一行。

</details>
