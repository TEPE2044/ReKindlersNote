# 出口：不是学完，是用上

这本书的终点不是"学完 TypeScript"，是在 `xinhuo_test_platform` 里改一处，自己跑一次。

## 怎么用上

你已经学过的八项内容，对应平台里的东西：

| 你学的 | 平台里的 | 改一处 |
| --- | --- | --- |
| 数组与双指针 | 用例列表的两头对调、轮转 | 把某个列表反转从 `reverse()` 改成手写的双指针 |
| 链表翻转 | 步骤链、配置链 | 把一条链的遍历改成翻转后的方向，看会不会断 |
| 二分查找 | 有序结果里定位 | 把某个 `findIndex` 改成二分 |
| 合并有序数组 | 两份报告合成时间线 | 把两个时间数组合成一个 |
| 栈、队列 | 测试步骤调度 | **把调度器改成队列实现** |
| 异步 | Playwright 等待 | 把一处 `setTimeout(0)` 改成正确的 await |
| 事件与 DOM | UI 交互绑定 | 把一组重复的事件监听改成委托 |
| 手写三件 | 搜索防抖、配置合并 | 给搜索框加防抖 |

## 先改这一个

找一个你平台里"按顺序执行测试步骤"的地方。它现在可能是数组遍历，也可能直接硬编码。把它改成你在 [ds-05 Q3](../01-数据结构五原型/ds-05-栈队列与括号.md) 手写的 `Queue`：

```js
const q = new Queue();
steps.forEach((s) => q.enqueue(s));

while (!q.isEmpty()) {
  const step = q.dequeue();
  // 执行 step
}
```

改完之后跑一次。如果失败，只可能是：

1. `dequeue` 返回 `undefined`，循环条件没写好。
2. 原数组被 `shift` 改掉了，你直接改的是入参。
3. 某个步骤里抛错，后面的步骤没跑。

把失败信息和改动贴过来，我再帮你看。

## 如果没改完

没关系。这本书的价值不是把平台重写一遍，是让你在改的时候，能看懂 AI 写的那一段。先保证这一处能跑通，再继续。
