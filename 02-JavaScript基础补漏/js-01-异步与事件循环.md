# 卷二 · JavaScript 01：异步与事件循环

> 异步最容易混淆的，是测试日志的打印顺序不等于实际发生顺序。

## 为什么先学这个

Playwright 里一个点击后面跟着断言。点击的回调、`Promise.then`、你自己写的 `setTimeout(0)`，不在同一条队列里。

`setTimeout` / `Promise.then` / 同步代码的标准顺序是 **cba**。写 UI 测试时这个顺序错了，断言就会等空。

## 三条队列，只记顺序

1. 同步代码先跑完。
2. 然后清空微任务：`Promise.then`、`queueMicrotask`、`async` 函数在 `await` 后面的部分。
3. 然后才拿一个宏任务：`setTimeout`、DOM 事件。

```js
setTimeout(() => console.log("a"), 0);
Promise.resolve().then(() => console.log("b"));
console.log("c");
```

打印是 `c`，然后 `b`，然后 `a`。不是 `c a b`。`setTimeout(0)` 不是「马上」，它排在所有微任务后面。

所以测试里写 `setTimeout(0)` 去等界面更新，经常等早了：Promise 回调还没跑，DOM 事件更没跑。

## `async` 不是返回那个数

```js
async function f() {
  return 1;
}

console.log(f() instanceof Promise); // true
console.log(typeof f());             // object
```

`typeof` 看不到 `pending`。`async` 把 `return 1` 包成已解决的 Promise。要值，用 `await` 或 `.then`，不要直接当数字比。

```js
async function readLevel() {
  return 12;
}

readLevel().then((n) => {
  console.log(n === 12); // true
});
```

## 一个和测试有关的顺序

```js
console.log("1 开始点录音");

Promise.resolve().then(() => {
  console.log("2 电平数据到了");
});

setTimeout(() => {
  console.log("3 界面刷新回调");
}, 0);

console.log("4 同步断言如果写在这里，电平还没到");
```

顺序是 1、4、2、3。第 4 行看起来在「点完之后」，实际上在微任务之前。这就是「日志里断言先于数据」的一种来源。

## `await` 暂停的是函数，不是线程

```js
async function run() {
  console.log("a");
  await Promise.resolve();
  console.log("b");
}

run();
console.log("c");
```

打印顺序是 `a`、`c`、`b`。`await` 让 `run` 函数暂停，把后面的代码挂到微任务队列，外面的同步代码继续跑。

所以 `await` 后面的代码，一定在「当前函数外所有同步代码」跑完之后才执行。

## 坑

- `typeof promise` 是 `object`，不是 `"promise"`，也不是 `pending`。
- `async` 函数即使只 `return 1`，调用结果也是 Promise。拿去和数字 `===` 一定是 false。
- 微任务插在 `setTimeout(0)` 前面。等渲染不要用 0 毫秒定时器冒充。
- `await` 暂停函数，不暂停全局线程。

## 练习

手写。

**Q1.** 不要运行，先把顺序写成三个字母，再跑下面这段对一下。写错了就把你原先猜的顺序留在作答里。

```js
setTimeout(() => console.log("a"), 0);
Promise.resolve().then(() => console.log("b"));
console.log("c");
```

**Q2.** 手写 `wait(ms)`，返回一个 Promise，`ms` 毫秒后 resolve。不要用别的库。

验收：

```js
console.log("before");
wait(20).then(() => console.log("after"));
console.log("sync");
```

必须先看到 `before`，再看到 `sync`，最后才是 `after`。

**Q3.** 写一个 `runInOrder(tasks)`，接收一个返回 Promise 的函数数组，按顺序执行，不要并行。

验收：

```js
function task(name, ms) {
  return () => wait(ms).then(() => console.log(name));
}

runInOrder([
  task("a", 30),
  task("b", 10),
  task("c", 20),
]);
// 必须按 a b c 打印，不能是 b c a
```

提示：用 `for...of` 加 `await` 最简单。不要写递归。

## 答案（先做完再看）

<details>
<summary>Q1 答案</summary>

`c b a`。同步 `c` 先，然后微任务 `b`，最后宏任务 `a`。

</details>

<details>
<summary>Q2 验收要点</summary>

- 返回一个 `new Promise`，`resolve` 交给 `setTimeout` 在 `ms` 毫秒后调用。
- 不要用同步循环或 `Date.now()` 差值去模拟等待，那不真等。
- 注意 `setTimeout` 的第一个参数直接传 `resolve`，不要包一层箭头函数再手动 `resolve()`。

</details>

<details>
<summary>Q3 验收要点</summary>

- 用 `for...of` 遍历任务数组，循环体里 `await task()`。
- 不能用 `Promise.all`，那会并行执行。
- 也不能用 `forEach` 加 `await`，因为 `forEach` 的回调里 `await` 不会阻塞外层循环。

</details>
