# 第四章 · 平台实战 04：断言判断是递归

> 平台里断言 JSON、断言界面数据，本质都是比较两个对象。`===` 不够用，要递归比。

## 为什么学

Playwright 的 `expect(locator).toHaveText()` 只能比单个值。但如果你要断言一个配置对象、一个接口返回、一组嵌套数据，就得自己写比较逻辑。

## 浅比较不够

```js
const a = { x: 1, y: { z: 2 } };
const b = { x: 1, y: { z: 2 } };

console.log(a === b);        // false
console.log(a.y === b.y);    // false
console.log(JSON.stringify(a) === JSON.stringify(b)); // true，但有坑
```

`JSON.stringify` 比较有两个问题：

1. 键顺序不同会误判。
2. 不能忽略某些字段（比如时间戳、随机 id）。

所以平台里要手写深比较。

## 递归深比较

```js
function deepEqual(a, b) {
  if (a === b) return true;
  if (typeof a !== "object" || typeof b !== "object") return false;
  if (a === null || b === null) return false;

  const keysA = Object.keys(a);
  const keysB = Object.keys(b);
  if (keysA.length !== keysB.length) return false;

  for (const key of keysA) {
    if (!keysB.includes(key)) return false;
    if (!deepEqual(a[key], b[key])) return false;
  }
  return true;
}

console.log(deepEqual({ x: 1, y: { z: 2 } }, { x: 1, y: { z: 2 } })); // true
```

注意：这里只处理普通对象和基本类型。数组也能走 `Object.keys`（返回下标）。函数、Date、RegExp 等要另外处理。

## 忽略字段

测试平台里常见需求：断言返回对象，但忽略 `createdAt` 这种每次运行都变的字段。

```js
function deepEqualIgnore(actual, expected, ignore = []) {
  if (ignore.length === 0) return deepEqual(actual, expected);
  if (
    typeof actual !== "object" ||
    typeof expected !== "object" ||
    actual === null ||
    expected === null
  ) {
    return false;
  }

  const keysA = Object.keys(actual).filter((k) => !ignore.includes(k));
  const keysB = Object.keys(expected).filter((k) => !ignore.includes(k));
  if (keysA.length !== keysB.length) return false;

  for (const key of keysA) {
    if (!keysB.includes(key)) return false;
    if (!deepEqualIgnore(actual[key], expected[key], [])) return false;
  }
  return true;
}
```

这个版本只忽略**顶层**字段。练习 Q2 要求忽略**任意层级**的字段，需要在递归时也传 `ignore`。

## 数组顺序

```js
console.log(deepEqual([1, 2, 3], [3, 2, 1])); // false
```

数组默认按顺序比。如果你要忽略顺序，需要先排序。但通常测试里顺序是要断言的。

## 坑

- `NaN === NaN` 是 false，但测试中通常认为两个 NaN 相等。要特殊处理。
- 循环引用会死循环。可以加一个 seen 集合。
- 不要过度封装，先把普通对象和数组比稳。

## 练习

手写。

**Q1.** 写一个 `deepEqualWithType(a, b)`，比较两个普通对象或数组，并额外处理 `Date` 和 `RegExp`：

- 两个 `Date` 如果时间戳相同，视为相等。
- 两个 `RegExp` 如果 `source` 和 `flags` 都相同，视为相等。

验收：

```js
console.log(deepEqualWithType({ a: 1 }, { a: 1 }));                            // true
console.log(deepEqualWithType({ d: new Date("2026-01-01") }, { d: new Date("2026-01-01") })); // true
console.log(deepEqualWithType({ r: /abc/g }, { r: /abc/g }));                  // true
console.log(deepEqualWithType({ r: /abc/g }, { r: /abc/i }));                  // false
console.log(deepEqualWithType([1, 2, 3], [1, 2, 3]));                          // true
console.log(deepEqualWithType([1, 2, 3], [3, 2, 1]));                          // false
```

**Q2.** 写一个 `deepEqualIgnore(actual, expected, ignoreKeys)`，忽略**任意层级**中名为 `ignoreKeys` 的 key。

验收：

```js
const a = {
  name: "x",
  meta: { createdAt: "2026-01-01", version: 1 },
};
const b = {
  name: "x",
  meta: { createdAt: "2026-02-02", version: 1 },
};

console.log(deepEqualIgnore(a, b, ["createdAt"])); // true
console.log(deepEqualIgnore(a, b, []));            // false
```

**Q3.** 让 Q1 的 `deepEqual` 能正确处理 `NaN`。

验收：

```js
console.log(deepEqual(NaN, NaN));           // true
console.log(deepEqual({ a: NaN }, { a: NaN })); // true
```

## 答案（先做完再看）

<details>
<summary>Q1 验收要点</summary>

- 先处理基本类型：`a === b` 直接返回 true。
- 处理 `null`：`null` 和对象要区分开，两者都是 `object`，但 `null` 没有 key。
- 处理 `Date`：比较 `a.getTime() === b.getTime()`。
- 处理 `RegExp`：比较 `a.source === b.source && a.flags === b.flags`。
- 普通对象/数组再递归比较每个 key。

</details>

<details>
<summary>Q2 验收要点</summary>

- 先排除 `null`：`actual` 或 `expected` 为 `null` 时直接返回 false（避免 `Object.keys(null)` 抛错）。
- 当前 key 在 `ignoreKeys` 中时，直接跳过这一对，不递归比较。
- 其他 key 递归比较值。
- 注意 `ignoreKeys` 要在每一层都生效，不只是顶层。

</details>

<details>
<summary>Q3 验收要点</summary>

- 在 `deepEqual` 开头加 `Number.isNaN(a) && Number.isNaN(b)` 的判断，两者都是 NaN 时返回 true。
- 用 `Number.isNaN` 而不是全局 `isNaN`，避免把字符串 `"NaN"` 误判。

</details>
