# 卷四 · 平台实战 03：状态流转是状态机

> 一个用例从创建到结束，状态会跳好几次。状态机能帮你拦住非法跳转。

## 为什么学

你的平台里，每个用例/步骤可能有这些状态：

```text
pending -> running -> passed
                -> failed
                -> skipped
```

如果失败了还能直接改成 running，说明状态机没写好，数据会乱。

## 最小状态机

```js
const transitions = {
  pending: ["running", "skipped"],
  running: ["passed", "failed"],
  passed: [],
  failed: [],
  skipped: [],
};

class Case {
  constructor() {
    this.state = "pending";
  }

  to(next) {
    const allowed = transitions[this.state];
    if (!allowed.includes(next)) {
      throw new Error(`不能从 ${this.state} 变成 ${next}`);
    }
    this.state = next;
  }
}

const c = new Case();
c.to("running");
c.to("passed");
console.log(c.state); // passed
```

状态机的核心只有两点：**当前状态是什么**，**允许转到哪些状态**。

## 添加数据和回调

```js
class Case {
  constructor(name) {
    this.name = name;
    this.state = "pending";
    this.error = null;
  }

  to(next, payload = null) {
    const allowed = transitions[this.state];
    if (!allowed.includes(next)) {
      throw new Error(`[${this.name}] 不能从 ${this.state} 变成 ${next}`);
    }
    this.state = next;
    if (next === "failed") this.error = payload;
  }
}
```

这样失败时可以把错误信息挂到用例上，报告里直接读。

## 从平台里抽象出来

你的平台调度器跑每个步骤时，应该做三件事：

1. 步骤开始前 `step.to("running")`。
2. 步骤成功后 `step.to("passed")`。
3. 步骤失败后 `step.to("failed", err)`。

任何其他跳转都抛错，说明调度逻辑有 bug。

## 坑

- 不要直接在代码里 `case.state = "passed"`，要过 `to()`。否则非法状态拦不住。
- 异步执行时，一个用例可能同时被触发两次，导致状态竞争。后面加队列解决。
- 状态图不要画太复杂。先从 `pending -> running -> passed/failed` 开始。

## 练习

手写。

**Q1.** 写一个 `createMachine(initialState, transitions)` 函数，返回一个状态机对象。

对象要有：

- `state`：当前状态。
- `to(next, payload)`：按 `transitions` 校验跳转。非法跳转抛错；跳转到 `failed` 时把 `payload` 存到 `error`；跳回 `pending` 时清空 `error`。
- `canTo(next)`：返回这次跳转是否被允许，不抛错、不改状态。

验收：

```js
const transitions = {
  pending: ["running"],
  running: ["passed", "failed"],
  passed: [],
  failed: ["pending"], // 可以重跑
};

const m = createMachine("pending", transitions);
console.log(m.state);                  // pending
console.log(m.canTo("running"));       // true
console.log(m.canTo("passed"));        // false

m.to("running");
m.to("failed", new Error("超时"));
console.log(m.error.message);          // 超时
console.log(m.canTo("pending"));       // true

m.to("pending");
console.log(m.error);                  // null
m.to("running");
m.to("passed");
console.log(m.state);                  // passed
```

## 答案（先做完再看）

<details>
<summary>Q1 验收要点</summary>

- `createMachine` 接收 `initialState` 和 `transitions`。
- 返回的对象要保存当前 `state` 和 `error`。
- `to(next, payload)` 先从 `transitions[this.state]` 查允许的目标状态；不允许就抛错，错误信息包含"不能从 X 变成 Y"。
- 抛错后状态应保持不变。
- 跳转后更新 `state`；跳转到 `failed` 时存 `payload`，跳回 `pending` 时清空 `error`。
- `canTo(next)` 只返回布尔值，不修改状态。
