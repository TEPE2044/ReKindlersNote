# 第三章 · JavaScript 07：类型系统只补一处

> 类型系统只补一处：浮点精度。这题错了会毁断言。

## 浮点精度

```js
console.log(0.1 + 0.2 === 0.3); // false
console.log(0.1 + 0.2);          // 0.30000000000000004
```

这不是 JS 的 bug，是所有用 IEEE 754 浮点数的语言的共性。二进制无法精确表示某些十进制小数。

## 对测试的影响

你的平台里如果有这样的断言：

```js
assert(level === 0.3);
```

很可能挂掉。不是数据错了，是精度问题。

## 正确做法

### 金额用整数分

```js
const price = 1000; // 10.00 元
const discount = 150; // 1.50 元
const result = (price - discount) / 100;
console.log(result); // 8.5
```

### 比较时定精度

```js
function roughlyEqual(a, b, epsilon = 1e-10) {
  return Math.abs(a - b) < epsilon;
}

console.log(roughlyEqual(0.1 + 0.2, 0.3)); // true
```

平台里读取电平、音量、频率这些浮点值时，用 `roughlyEqual` 比直接 `===` 稳。

## typeof 的局限

```js
console.log(typeof null);           // object
console.log(typeof NaN);            // number
console.log(typeof Promise.resolve()); // object
```

`typeof` 只能粗分。要精确判断：

- 数组用 `Array.isArray(x)`
- `null` 用 `x === null`
- NaN 用 `Number.isNaN(x)`
- Promise 用 `x instanceof Promise`

## 坑

- 不要用 `==` 做比较，隐式转换规则太多。
- `parseInt("08")` 在现代浏览器是 8，但老代码或面试题里可能出幺蛾子。直接用 `Number("08")` 更清楚。
- 浮点数不要用 `toFixed` 做精确计算，它是格式化，不是数学运算。

## 练习

手写。

**Q1.** 写一个 `assertRoughly(actual, expected, epsilon = 1e-10)`，如果差值超过 epsilon 就抛错。

验收：

```js
assertRoughly(0.1 + 0.2, 0.3);       // 不抛
assertRoughly(0.1 + 0.2, 0.3001);    // 抛
```

**Q2.** 写一个 `isPromise(x)`，准确判断一个值是不是 Promise。

验收：

```js
console.log(isPromise(Promise.resolve())); // true
console.log(isPromise({ then() {} }));     // false（不是真 Promise）
console.log(isPromise(null));              // false
console.log(isPromise("pending"));         // false
```

提示：用 `instanceof Promise`，不要用 `typeof`。

**Q3.** 写一个 `centsToYuan(cents)`，把整数分转成元字符串，保留两位小数。

验收：

```js
console.log(centsToYuan(1000));  // "10.00"
console.log(centsToYuan(8));     // "0.08"
console.log(centsToYuan(12345)); // "123.45"
```

## 答案（先做完再看）

<details>
<summary>Q1 验收要点</summary>

- 用 `Math.abs(actual - expected)` 算差值。
- 差值大于等于 `epsilon` 时抛错。
- 不要把 `epsilon` 设成 0，也不要直接用 `===` 比浮点。

</details>

<details>
<summary>Q2 验收要点</summary>

- 用 `x instanceof Promise` 判断。
- `typeof` 会把 Promise 误判成 `object`。
- 有 `then` 方法的对象不一定是 Promise，不要用这个特征判断。

</details>

<details>
<summary>Q3 验收要点</summary>

- 先把分转成元：`cents / 100`。
- 用 `toFixed(2)` 格式化成两位小数。
- 这里用 `toFixed` 是**格式化展示**，不是做精确计算；因为输入是整数分，除 100 后不会有浮点问题。

</details>
