# 卷三 · JavaScript 09：模块

> 测试脚本一多，必然要拆文件。CommonJS 和 ES Module 混着用，是 Node 项目的日常。

## 两种模块系统

### CommonJS（Node 传统）

```js
// math.js
function add(a, b) {
  return a + b;
}

module.exports = { add };
```

```js
// main.js
const { add } = require("./math");
console.log(add(1, 2));
```

`require` 是同步的，运行时加载。文件扩展名 `.js` 可以省略。

### ES Module（现代标准）

```js
// math.mjs
export function add(a, b) {
  return a + b;
}
```

```js
// main.mjs
import { add } from "./math.mjs";
console.log(add(1, 2));
```

`import` 是静态的，编译时确定依赖。文件名要写完整，`.mjs` 不能省略。

## Node 里怎么混用

如果你的 `package.json` 里没有 `"type": "module"`，Node 默认把 `.js` 当 CommonJS。要写 ES Module，要么：

1. 把文件改成 `.mjs`。
2. 在 `package.json` 里加 `"type": "module"`，这样 `.js` 也当 ES Module。

一旦你开了 `"type": "module"`，整个项目的 `.js` 文件都必须用 `import/export`，不能再混 `require`。

## 测试脚本里的常见写法

老项目或旧模板的 Playwright 配置文件常见 CommonJS；新版模板（如 `npm init playwright@latest`）可能直接生成 ESM 或 TypeScript。关键是看文件后缀和 `package.json` 里的 `"type"`：

```js
// playwright.config.js（CommonJS 写法示例）
module.exports = {
  testDir: "./tests",
  timeout: 30000,
};
```

测试文件本身常用 ES Module：

```js
// example.spec.js
import { test, expect } from "@playwright/test";

test("basic", async ({ page }) => {
  await page.goto("/");
});
```

所以你要能读懂两种写法，但不用写得很复杂。

## 坑

- `require` 可以写条件分支里，`import` 不行（顶层静态）。
- `require("./math.js")` 和 `require("./math")` 都行；`import` 必须写对路径。
- 循环引用时，CommonJS 可能返回部分初始化的对象，容易出 undefined。

## 练习

手写。

**Q1.** 创建两个文件：

- `utils.js`：用 CommonJS 导出一个 `sleep(ms)` 函数，返回一个 `ms` 毫秒后 resolve 的 Promise。
- `main.js`：引入 `sleep`，先打印 `start`，等 50ms 后打印 `end`。

运行 `node main.js`，验收输出：

```text
start
end
```

**Q2.** 把 Q1 改成 ES Module。文件后缀改成 `.mjs`，`utils.mjs` 用 `export`，`main.mjs` 用 `import`。

运行 `node main.mjs`，验收输出同样是：

```text
start
end
```

**Q3.** 下面这段代码运行时不会抛错，`main.js` 会输出 `2`，但 `getA()` 会返回 `undefined`。写出原因。

```js
// a.js
const { b } = require("./b");
module.exports = { a: 1, getB: () => b };

// b.js
const { a } = require("./a");
module.exports = { b: 2, getA: () => a };

// main.js
const { getB } = require("./a");
console.log(getB());
```

## 答案（先做完再看）

<details>
<summary>Q1 / Q2 验收要点</summary>

- CommonJS 用 `module.exports` 和 `require`。
- ES Module 用 `export` 和 `import`。
- ES Module 文件用 `.mjs`，或在 `package.json` 里加 `"type": "module"`。

</details>

<details>
<summary>Q3 答案</summary>

循环引用。加载 `a.js` 时，它先 `require("./b")`。`b.js` 又 `require("./a")`，但此时 `a.js` 还没执行完 `module.exports`，所以 `b.js` 拿到的 `a` 是部分初始化的对象（此时只有空对象）。

结果 `getB()` 返回 `2`，但 `b.js` 里的 `getA()` 返回 `undefined`。

解决：不要在模块顶层互相 require，或把依赖改为函数内部再 require。

</details>
