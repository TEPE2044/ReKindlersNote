# 第三章 · JavaScript 08：错误处理

> 测试工程师读日志，一半时间在跟错误打交道。错误信息读不懂，排查就慢。

## 为什么学这个

你的平台跑用例，失败时要给出可用信息。`try/catch`、`Promise.catch`、`async/await` 里的错误，如果抓错地方，日志里就是一堆 undefined 或 [object Object]。

## try / catch

```js
try {
  JSON.parse("不是 json");
} catch (err) {
  console.log(err.message);
}
```

`catch` 抓到的是抛出的值。如果抛出的是字符串，err 就是字符串；如果抛出的是对象，err 就是那个对象。尽量抛 `Error` 实例，不要抛字符串。

```js
// 不好
throw "出错了";

// 好
throw new Error("出错了");
```

## Promise 错误

```js
Promise.reject(new Error("失败"))
  .then(() => console.log("不会执行"))
  .catch((err) => console.log(err.message)); // 失败
```

`.catch` 会捕获前面链上任何 `.then` 里抛出的错误。

## async / await 的错误

```js
async function run() {
  try {
    await Promise.reject(new Error("失败"));
  } catch (err) {
    console.log(err.message);
  }
}
```

`await` 后面如果 Promise 被拒绝，会抛错。用 `try/catch` 包起来。

坑：如果一个 async 函数里抛错但没有 `try/catch`，错误会变成未处理的 Promise 拒绝。

```js
async function bad() {
  throw new Error("boom");
}

bad(); // UnhandledPromiseRejection
```

## 测试里的常见错误

```js
async function checkLevel() {
  const level = await readLevel(); // 假设返回 Promise
  if (level < 10) {
    throw new Error(`电平过低：${level}`);
  }
  return level;
}
```

错误信息里要包含具体的值，不要只写"电平过低"。否则你拿到日志还是不知道当时是多少。

## 全局捕获

```js
process.on("unhandledRejection", (err) => {
  console.error("未处理的 Promise 拒绝:", err);
  process.exit(1);
});
```

在 Node 脚本入口加这个，能拦住漏掉的 async 错误。测试框架通常已经做了，但自己写小工具时要记得。

## 坑

- `catch` 里又抛错，会传到下一个 `catch`。
- `finally` 里的代码无论成功失败都会执行，但 `finally` 里如果 `return`，会覆盖 `try` 里的 `return`。
- `JSON.stringify(err)` 通常得到 `{}`，要看错误信息用 `err.message` 和 `err.stack`。

## 练习

手写。

**Q1.** 写一个 `parseJSONSafe(str)`，解析失败时返回 `null`，不抛错。

验收：

```js
console.log(parseJSONSafe('{"a":1}'));    // { a: 1 }
console.log(parseJSONSafe('不是 json'));   // null
console.log(parseJSONSafe(null));          // null
```

**Q2.** 写一个 `runWithTimeout(fn, ms)`，执行 `fn()`，如果 `ms` 毫秒内没完成，就抛错 `Timeout after ${ms}ms`。

验收：

```js
async function slow() {
  await new Promise((r) => setTimeout(r, 100));
  return "done";
}

runWithTimeout(slow, 50).catch((err) => {
  console.log(err.message); // Timeout after 50ms
});
```

提示：用 `Promise.race`。

**Q3.** 写一个 `wrapError(original, context)`，返回一个新 Error，message 包含 `context` 和原 error 的 message。

验收：

```js
const err = new Error("文件不存在");
const wrapped = wrapError(err, "加载配置");
console.log(wrapped.message); // 加载配置: 文件不存在
```

## 答案（先做完再看）

<details>
<summary>Q1 验收要点</summary>

- 用 `try/catch` 包 `JSON.parse(str)`，解析失败返回 `null`。
- `catch` 可以省略参数。
- 输入 `null` 时 `JSON.parse(null)` 返回 `null`；输入 `undefined` 会抛错，所以非字符串输入建议先返回 `null`。

</details>

<details>
<summary>Q2 验收要点</summary>

- 用 `Promise.race([fn(), timeout])` 让两个 Promise 竞争。
- 超时 Promise 在 `ms` 毫秒后 reject，message 为 `Timeout after ${ms}ms`。
- 生产环境里要记得在 `fn()` 完成后 `clearTimeout(timer)`，否则 Node 进程会多等定时器结束。

</details>

<details>
<summary>Q3 验收要点</summary>

- 新建一个 `Error`，message 写成 `${context}: ${original.message}`。
- 把原 error 挂到新 error 的 `cause` 属性，方便保留完整 stack。
- 不要直接 `throw original`，那样上下文会丢。

</details>
